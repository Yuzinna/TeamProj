# TeamProj Constitution (프로젝트 규칙)

## 핵심 원칙 (Core Principles)

### I. C# 스크립트 사용
모든 게임 로직과 동작은 C# 스크립트를 사용하여 구현해야 합니다. 이는 일관성을 보장하고 Unity 엔진의 모든 기능을 활용하기 위함입니다.

### II. 프리팹(Prefab) 기반 개발
모든 게임 오브젝트는 프리팹으로 생성되어야 합니다. 이는 재사용성을 높이고, 씬 관리를 용이하게 하며, 업데이트를 간소화합니다.

### III. 씬(Scene) 관리
각 씬은 독립적이어야 하며, 특정 레벨이나 메뉴를 나타내야 합니다. 명확한 씬 로딩/언로딩 전략이 마련되어 있어야 합니다.

### IV. 에셋(Asset) 파일 네이밍 컨벤션
모든 에셋 파일(스크립트, 머티리얼, 텍스처, 모델 등)은 일관된 네이밍 컨벤션을 따라야 합니다. (예: `타입_이름_변형`, `Script_Player_Movement`처럼).

### V. Git을 사용한 버전 관리
프로젝트는 Git을 사용하여 관리해야 합니다. 모든 변경사항은 명확하고 설명적인 메시지와 함께 커밋되어야 합니다.

### VI. 스크립트 파일 위치
새로운 스크립트는 항상 `Assets/02.Scripts/Proj` 폴더 내의 적절한 하위 폴더에 위치해야 합니다. 이는 깨끗하고 정리된 프로젝트 구조를 유지합니다.

### VII. 문서 및 주석 언어
모든 문서와 코드 내 주석은 한국어로 작성되어야 하지만, 클래스명, 함수명, 변수명과 같은 코드 식별자는 **반드시** 영어(로마자)를 사용해야 합니다. 단, 주석과 문서에서만 기술 용어는 영어 원문과 병기하는 것을 **권장**합니다.

### VIII. 에셋 폴더 네이밍 컨벤션
`Assets` 폴더 바로 아래에 새로운 폴더를 추가할 때는 **반드시** `0x.` 형식의 순서 번호를 접두사로 붙여야 합니다. (예: `01.Scenes`, `02.Scripts`).

## 개발 워크플로우 (Development Workflow)

모든 새로운 기능이나 버그 수정은 별도의 브랜치에서 개발되어야 하며, 검토 및 승인 후 메인 브랜치에 병합되어야 합니다.

## 품질 게이트 (Quality Gates)

병합 전, 모든 코드는 최소 한 명의 다른 팀원에게 검토받아야 합니다. 기능은 테스트 가능해야 하며 기존 기능을 손상시키지 않아야 합니다.

## 거버넌스 (Governance)

이 규칙 문서는 개발 관행에 대한 단일 진실 공급원(single source of truth)입니다. 모든 개정안은 팀의 논의와 승인이 필요합니다.
